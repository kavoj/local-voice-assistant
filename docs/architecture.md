# 架构设计

## 分层总览

```
┌─────────────────────────────────────────────┐
│ 感知层 sensing/                              │
│   唤醒词检测 (Porcupine)  视觉感知 (YOLO+人脸) │
└──────────────┬──────────────────────────────┘
               │ 触发事件
┌──────────────▼──────────────────────────────┐
│ 触发仲裁层 state_machine.py                  │
│   待命 → 感知触发 → 主动问候 → 多轮对话 → 冷却 │
│   冷却节流 · 场景判断 · 防打扰                 │
└──────────────┬──────────────────────────────┘
               │ 会话开启/结束
┌──────────────▼──────────────────────────────┐
│ 语音交互层 voice/                            │
│   拾音+VAD → ASR → (文本) → TTS → 播报        │
└──────────────┬──────────────────────────────┘
               │ 转写上行 / 回复下行
┌──────────────▼──────────────────────────────┐
│ 大脑层 brain/                                │
│   EchoBrain(默认) / WorkBuddyBrain(生产)      │
│   会话上下文 · 记忆 · 工具执行                 │
└──────────────┬──────────────────────────────┘
               │ 每轮交互落盘
┌──────────────▼──────────────────────────────┐
│ 数字分身数据层 twin/                          │
│   schema → recorder(JSONL) → export(训练集)   │
└─────────────────────────────────────────────┘
```

## 状态机

状态：`IDLE`（待命）→ `ENGAGED`（对话中）→ 冷却回到 `IDLE`

事件与转移：

| 当前状态 | 事件 | 动作 | 下一状态 |
|---------|------|------|---------|
| IDLE | WAKE_WORD | 立即响应，开启会话 | ENGAGED |
| IDLE | PERSON_DETECTED | 过节流检查 → 主动问候 | ENGAGED |
| ENGAGED | TURN_TIMEOUT（如 30s 无声） | 结束会话 | IDLE（写入冷却名单） |
| ENGAGED | SESSION_END | 结束会话 | IDLE |
| IDLE | PERSON_DETECTED（冷却期内） | 忽略，不重复打扰 | IDLE |

冷却规则（可配置）：
- 同一身份在 `twin.cooldown_seconds`（默认 300s）内不重复主动搭话
- 唤醒词触发不受冷却限制（用户主动优先）
- 问候语从话术池轮换，避免机械重复

## 可移植性设计

1. **配置驱动**：所有路径、阈值、提供方均来自 `config/settings.yaml`，代码内不硬编码绝对路径
2. **接口 + 桩**：感知/语音/大脑均为抽象接口，桩实现零依赖可跑，替换实现即可升级真机
3. **console 模式**：stdin/stdout 模拟整条链路，任何无硬件环境均可端到端演示与测试
4. **数据本地化**：`data/` 目录自包含，打包即带走

## 对接 WorkBuddy

- `brain/workbuddy_brain.py`：`ask(text, context) -> str`，将转写文本送入 WorkBuddy 会话，取回回复
- WorkBuddy 侧保留长期记忆与工具执行（日程、消息、文件），语音前端只做「耳朵和嘴」
- 数字分身训练成熟后，可让 twin 导出的微调模型替换/增强大脑的人格层
