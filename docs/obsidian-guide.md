# 与 Obsidian 结合：让本地知识库可视化、可编辑、可沉淀

## 为什么推荐 Obsidian

本项目知识库就是「一目录 markdown」——而 Obsidian 天生就是本地 markdown 库：
**免费、纯本地、所见即所得、支持双向链接**。让助手读 Obsidian 里的制度文档，
就等于让助手读「你能看到、能编辑、能版本管理」的知识，而不是黑盒数据库。

关系一句话：**Obsidian 负责“人看人写”，数字助理负责“人问机答”，两者读同一份 markdown。**

## 三步对接

### 1. 安装 Obsidian（免费）

- macOS / Windows / Linux 均支持：https://obsidian.md/download

### 2. 在引导向导中选择对接（推荐）

一键部署向导 `scripts/quickstart.py` 里选「对接 Obsidian 本地知识库」并填入库目录：

```
你的 Obsidian 库目录: ~/Documents/企业知识库
```

向导自动做三件事：
1. 在库内创建 `00-数字助理知识库/` 文件夹
2. 把种子制度文档（报销/考勤/入职/FAQ…）拷入该文件夹
3. 把 `config/settings.yaml` 的 `enterprise.knowledge_dir` 指向该文件夹

### 3. 手动对接（等价做法）

```yaml
# config/settings.yaml
enterprise:
  knowledge_dir: "/Users/你/Documents/企业知识库/00-数字助理知识库"
```

> Windows 示例：`D:\\ObsidianVault\\00-数字助理知识库`（注意反斜杠转义，或直接用正斜杠 `D:/ObsidianVault/...`）

## 推荐库结构

```
📁 企业知识库（Obsidian Vault）
├── 00-数字助理知识库/        ← 助手只读这一目录（enterprise.knowledge_dir）
│   ├── 报销流程.md   ├── 考勤制度.md   ├── 入职指南.md
│   └── 常见问题.md
├── 01-制度原文/              ← 人的管理区，可放正式制度全文
├── 02-会议纪要/
└── 03-员工手册/
```

## 使用循环（即换即用）

1. 你在 Obsidian 里新建/编辑 markdown（用 `# 标题` 分节、空行分段，助手按段落检索）
2. 保存后，**下次启动助手**即生效（无需任何重建/索引命令）
3. 问「报销怎么走流程」→ 助手返回段落 +（出处：《报销流程》日常报销）

### 给文档写对格式（影响检索质量）

- 一个主题一个文件，文件名即主题：`报销流程.md` 优于 `制度集合.md`
- 用二级/三级标题分小节；小节间用空行隔开
- 一句话一行的事实型内容检索命中率最高

## 进阶玩法

| 玩法 | 做法 |
|------|------|
| 团队共享制度库 | 把库目录放进公司共享盘 / Git 仓库，全员可更新制度 |
| 文档溯源 | 助手答案永远带《文件名·小节》，可一键跳到 Obsidian 原文核对 |
| 个人知识沉淀 | 对话中问到的、助手补充的内容，随手粘回 Obsidian 形成第二大脑 |
| 双链组织 | Obsidian 内用 `[[报销流程]]` 互相链接，检索不受影响（助手按纯文本段落处理） |
| 数字分身数据 | 训练集导出为 JSONL 后可归档进库内 `04-训练数据/`（辅助文件按需） |

## 边界说明

- 助手检索基于纯文本段落（忽略 Obsidian 的 `[[双链]]`、Dataview 等插件语法渲染）
- 实时热更新：当前进程启动时加载一次知识库；改文档后新开会话即生效（本地服务版会升级为监听热载）
- 图片/PDF 不在知识库检索范围，需先转成 markdown 文本
